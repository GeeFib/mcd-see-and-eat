# 🍔 看见什么吃什么

> 每天中午站在麦当劳菜单前发呆十分钟，最后还是点了上次那个。
> 这个 Skill 替你把这事想清楚：**先放一段开餐曲把食欲叫起来，
> 再按《中国居民膳食指南》算出你一天该吃多少，
> 用这家门店当前真的在卖的餐品配出来，顺手把能用的券也省了。**

## 它解决什么

| 打工人真实痛点 | 本项目的做法 |
| --- | --- |
| 选择困难，每次都点一样的 | 直接给三套方案，各自写清取舍理由；不满意说一句**「换一批」** |
| 站在菜单前毫无食欲 | 跑搭配时放一段**「看见什么吃什么」开餐曲**，先把馋虫叫起来 |
| 想控体重但不知道该吃多少 | 按身高体重年龄算 BMR/TDEE，给出能量与三大营养素目标 |
| 「麦当劳不健康」是个模糊印象 | 拆成能量/蛋白质/脂肪/碳水/钠/钙六项逐项对比膳食指南 |
| 有券但不知道自己能不能用 | 查门店券 → 对齐餐品 → **用算价接口实测券后价**，并说清「少付钱」还是「同价多拿一份」 |
| 配好了还得自己打开 App 一个个点 | 方案自带餐品编码与券核销三件套，可直接调 MCP 算价、领券、下单 |
| 营养建议全是套话 | 明确告诉你：**钠大概率会超 2000mg，膳食纤维一定不够** |

## 效果示例

> 175cm / 72kg / 28 岁男性，久坐办公，维持体重，深圳蛇口网谷餐厅（实时数据，2026-10-16）

```
方案 A · 均衡日常                                    预估 ¥136.5
  早餐  火腿扒麦满分 + 大杯玉米杯 + 大杯怡泉+C
  午餐  麦香鱼 + 中薯条 + 热浓浓抹茶牛奶大杯
  晚餐  培根蔬萃双层牛堡 + 小杯玉米杯 + 可乐大杯
  合计  2182 kcal｜蛋白 78g｜钠 2202mg｜钙 834mg
  🧧 中薯条可用「中薯条买一送一」：¥13.5 不变，多送 1 份
     （价值 ¥13.5，代价是额外 289 kcal / 165 mg 钠 —— 已如实算给你看）

方案 B · 高蛋白保肌                                  预估 ¥148.5
  蛋白质 94g（目标抬到约 1.35 g/kg），代价是钠升到 2498mg

方案 C · 低钠轻负担                                  预估 ¥123.0
  钠压到 2037mg，代价是能量降到 1893 kcal

说一句「换一批」（--reroll）：
  早餐  原味板烧鸡腿麦满分 → 原味板烧鸡腿炒双蛋堡
  午餐  麦香鱼 → 麦香鸡
  晚餐  培根蔬萃双层牛堡 / 双层深海鳕鱼堡 → 麦香鸡 / 麦香鱼
  全天钠 2202 → 2292mg：换了新面孔，钠只多 90mg
  （池子里找不到钠相近替代的那几餐，保留原主食并如实写出来，
    而不是为了「不重样」把钠换高一大截）
```

同时会明确给出：钠超出上限 → 建议其他餐次多吃蔬果补钾、多喝水；
膳食纤维麦当劳本身吃不够 → 需要自行补充。

## 三个「别人不会做」的细节

### 1. 开餐曲：把「看见什么吃什么」唱出来

跑 skill 时会先播一段约 3 秒的开场小曲（`src/seeandeat/anthem.py`
用正弦波现场合成的五声音阶动机，**不含任何第三方旋律**，因此可以随仓库分发）。

想换成原曲，把你自己合法持有的音频文件指给它即可，本项目不分发原曲：

```bash
export SEEANDEAT_ANTHEM=/path/to/看见什么吃什么.m4a
```

HTML 报告顶部还有一个「▶ 开餐曲」按钮（浏览器要求手点），
用的是同一段动机的 WebAudio 实现，不需要任何音频文件。

关掉：`--no-sound` 或 `export SEEANDEAT_NO_ANTHEM=1`。

### 2. 换一批：换新的前提是不把健康换掉

说「换一批」时加 `--reroll`：

- **换掉最近两批点过的主食**，保证真的不是同一套；
- **有券的餐品不做回避** —— 否则等于自己把钱扔掉；
- **替代主食的钠超基准就扣分**：以「被换掉的主食里钠最低的那个」为基准线，
  替代品明显高于它就在打分阶段吃惩罚。这条是实测逼出来的：
  第一版只有「换掉」，结果门店里最省钠的汉堡一被禁掉，优化器就顺手挑了
  1041mg 钠的板烧鸡腿堡，全天钠从 2230 直接飙到 2885mg；
- **一个餐次换不动就如实说**：池子里没有钠相近的替代时保留原主食，
  并在报告里写明「硬换会明显抬高这一餐的钠」，同时给出「本批主食变化」清单；
- 束搜索改成**按主食分层取样**：低钠主食不再独占全部候选名额，
  否则午晚餐会因为束里只剩它而点两遍同一只汉堡；
- 批次记忆存在 `~/.mcd-see-and-eat/batches.json`（只有餐品名，无 Token）。

连换 5 批实测：主食批内重样 0 次，全天钠始终落在 2040–2560mg，
没有为了「不重样」出现某一批钠突然翻倍。换到第 4 批左右会开始绕回，
这是**正常的**：门店里「既达标又不重样」的组合有限。
项目选择如实说明，并建议换门店或换目标，而不是假装有无限组合。

### 3. 优惠券：把「划算」说成两种

这是最容易骗人的地方，本项目用实测数据把口径钉死：

| 类型 | 表现 | 券后实付 | 说法 |
| --- | --- | --- | --- |
| 特惠 / 立减 | 同样的东西少付钱 | 下降 | 「实付 ¥X，少付 ¥Y」 |
| 买一送一 / 第二份半价 | 价格不变，多给你一份 | **不变** | 「钱一样，但多拿到一份（额外 A kcal / B mg 钠）」 |

实测：「中薯条买一送一」算价返回商品价 13.5、优惠 13.5 ——
是**花一份钱拿两份**，不是 27 元减到 13.5 元。所以报告里不会把买一送一说成打折，
多出来的那份热量和钠也照实列出。

券与餐品的匹配只认能确定的规格：**冰/热、大杯/中杯、5 块/4 块对不上就不算**。
真实案例：门店券「9.9元中杯冰美式」对应冰美式，而当天菜单只有热美式 → 判定用不上，
宁可少省几块钱，也不告诉用户「这张券你能用」。

匹配是双向的：券叫「双层深海鳕鱼堡」而餐品是「深海鳕鱼堡」也不算 ——
「双层」这类词会同时改变份量和营养。反过来「原味板烧鸡腿堡」与「板烧鸡腿堡」
被判为同一款，因为麦记本身就是同一 SKU 的两个写法。
这 20 条判定都写进了 `scripts/selftest.py`，改匹配规则必须让自检保持全绿。

## 三套方案为什么不一样

不是随机扰动，是**三种明确的取舍**（预设会同时调整目标值与惩罚权重）：

| 预设 | 目标调整 | 权重调整 | 适合 |
| --- | --- | --- | --- |
| `balanced` 均衡日常 | — | 全面均衡 | 闭眼选这个 |
| `high_protein` 高蛋白保肌 | 蛋白质 ×1.35 | 蛋白质不足惩罚 ×3 | 训练日、减脂期 |
| `low_sodium` 低钠轻负担 | 钠上限 ×0.85 | 钠超标惩罚 ×9 | 体检钠偏高、今天别的两餐也咸 |

## 快速开始

### 1. 申请 MCP Token

到 [麦当劳 MCP 开放平台](https://open.mcd.cn/mcp) 用手机号登录 → 控制台 → 激活 → 复制 Token。

### 2. 配置

```bash
export MCD_MCP_TOKEN=<你的 Token>
```

（在 WorkBuddy 里用则参考 `mcp-config.example.json` 配置连接器，Token 只走环境变量。）

### 3. 跑

```bash
git clone https://github.com/<你的账号>/mcd-see-and-eat.git
cd mcd-see-and-eat

# 三餐都在麦当劳解决（自动放开餐曲）
python scripts/plan.py --sex male --age 28 --height 175 --weight 72 \
    --html today.html

# 不满意？换一批，并优先挑有券的组合
python scripts/plan.py --sex male --age 28 --height 175 --weight 72 \
    --reroll --html next.html

# 只在麦当劳吃午餐，减脂，不喝可乐
python scripts/plan.py --sex female --age 30 --height 162 --weight 55 \
    --goal cut --meals lunch --exclude 可乐 --html today.html
```

无第三方依赖，Python 3.9 起可用，3–6 秒出结果。`--html` 生成的报告是单文件，手机打开也能看。

**没有 Token 也能体验**：加 `--offline`，用仓库 `data/` 下的真实快照
（2026-10-16 采集，含菜单、营养表与门店券）跑完整流程，连券和「换一批」都能演示。

### 3.5 自检（可选）

```bash
python scripts/selftest.py
```

不需要网络和 Token，跑三组断言：券与餐品的 20 条匹配用例、
「换一批」连换 5 批的批内不重样与钠上限、离线全链路能否出报告。
这三组正是最容易「看起来对、实际上错」的地方（详见下面「别人不会做」第 3 节）。

### 4. 看券 / 领券（可选）

```bash
python scripts/coupons.py --store-code 1420621            # 有哪些券、能不能对上餐品
python scripts/coupons.py --store-code 1420621 --quote    # 券后价实测
python scripts/coupons.py --claim                         # 一键领取麦麦省可领券（会写入你的账号）
```

### 5. 下单（可选）

```bash
python scripts/order.py --plan today.json --meal lunch                    # 查券 + 算价
python scripts/order.py --plan today.json --meal lunch --use-coupon          # 带上券核销
python scripts/order.py --plan today.json --meal lunch --use-coupon --confirm # 真下单（会扣款）
```

## 参数

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--sex` | male / female | male |
| `--age` | 年龄 | 28 |
| `--height` | 身高 cm | 172 |
| `--weight` | 体重 kg | 68 |
| `--activity` | sedentary / light / moderate / active | sedentary |
| `--goal` | cut / maintain / bulk | maintain |
| `--meals` | 哪几餐在麦当劳解决，逗号分隔 | breakfast,lunch,dinner |
| `--preset` | 只要某一套：balanced / high_protein / low_sodium | 全部三套 |
| `--exclude` | 忌口关键词 | — |
| `--dessert` | 允许加甜品 | 关 |
| `--reroll` | **换一批**：回避上一批主食，优先挑有券组合 | 关 |
| `--reset-batch` | 清空换一批的记忆 | 关 |
| `--no-coupon` | 不查优惠券 | 会查 |
| `--no-sound` | 不放开餐曲 | 会放 |
| `--store-code` / `--keyword` | 指定门店 / 搜门店 | 收藏门店第一家 |
| `--offline` | 用本地快照，不请求 MCP | 关 |
| `--json` / `--md` / `--html` | 输出路径 | 直接打印 Markdown |

## 它是怎么工作的

```
                 ┌────────────────── 麦当劳 MCP Server ──────────────────┐
用户画像           │  query-nearby-stores    门店                          │
性别/年龄/身高/体重 │  now-time-info          服务器时间                     │     营养目标
活动量/目标    ──┐ │  list-nutrition-foods   160 条餐品营养                 │  ┌──（膳食指南 2022 + DRIs 2023）
                │ │  query-meals  ×3        早/午/晚分时菜单 + 价格         │  │   能量 / 三大营养素 / 钠 / 钙
                │ │  query-store-coupons    门店可用券 + 券商品编码          │  │
                │ │  calculate-price        带 couponId 实测券后价          │  │
                │ └──────────────────────────────────────────────────────┘  │
                │                        │                                  │
                │                        ▼                                  │
                │      双向对齐：营养表 × 在售菜单；券 × 餐品池                │
                │      剔除套餐与营养表未覆盖的新品，绝不估算                    │
                │                        │                                  │
                └────────────────────────┼──────────────────────────────────┘
                                         ▼
                  束搜索：每餐「主食+小食+饮品」穷举 → 保留 Top-56
                          三餐再组合 → 按整日目标 + 供能比 + 重复度
                                       + 换一批回避 + 券偏好 打分
                                         ▼
                     三套方案 + 券后价 + Markdown / HTML 报告
                       （同时后台播放开餐曲）
```

关键点：

- **分时菜单**：麦当劳早餐只供应到约 10:30，直接查「当前菜单」配不出早餐。
  本项目按早/午/晚分别用 `query-meals` 的 `reservationDate` 拉对应时段菜单。
- **以营养表为规划单位**：`可乐中杯/大杯`、`薯条小/中/大` 营养不同，
  营养表条目规格最精确，再反查菜单拿价格与编码，保证「配得出来就点得到」。
- **券的核销三件套**：`calculate-price` 要求 `items[]` 传**券商品自己的 productCode**，
  并同时带 `couponId` + `couponCode`。这一点在官方文档里不显眼，
  是本项目靠实测摸出来的（见 `MCP_INTEGRATION.md`）。
- **不猜数**：营养表里查不到的一律剔除，报告里明确列出被剔除的原因。

## 目标用户

- 工作日靠麦当劳解决一顿或几顿、又在意体重和健康的城市打工人
- 健身/减脂人群：需要精确控制蛋白质和能量，但不想顿顿自己做饭
- 需要控钠但又离不开快餐的人（本项目会如实告诉你哪里压不住）
- 把「今天吃什么」当成决策负担的人

## 作为 WorkBuddy Skill 使用

把本仓库放到 `~/.workbuddy/skills/mcd-see-and-eat/` 后，直接在对话里说：

> 「我 175、72 公斤，久坐，帮我配今天的麦当劳三餐」

Skill 会先向你要齐身高体重等信息，再跑完整流程并把 HTML 报告推给你；
不满意就说「换一批」，它会换掉上一批主食并优先挑有券的组合。
